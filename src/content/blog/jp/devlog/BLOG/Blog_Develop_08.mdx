## エラー修正: dynamic routes関連問題
前の記事をクリックしたとき、dynamic routes関連のエラーが発生する問題を見つけました。

1. 前の記事リンクをクリックすると、見ている記事の`.../ALGO_BOT/Algorithm_Bot_05.mdx/Algorithm_Bot_04`のようにURLが誤って生成される問題でした。
2. これを解決するため、前の記事リンクを生成するときに`../Algorithm_Bot_04.mdx`のような相対パスを使うよう修正しました。
3. Slugifyによって大文字ではなく小文字のURLが生成され、同じく404エラーが出ました。

AIに聞いてみると、この問題を解決するには2つの選択肢があるとのことでした。一つはファイル名をすべて小文字に変える方法、もう一つはFrontmatterでslugを強制指定する方法です。

ただ、そこまでする必要があるのかと思い、`[前の記事](../algorithm_bot_04)`のようにリンク自体を小文字に変えたところ、問題が解決しました。
AIに先に聞くより、自分で考えてから答えが出ないときに聞く習慣を身につける必要がありそうです。

## カテゴリ別記事一覧機能追加
どう作るべきか悩みました。最初に考えたのは、Frontmatterにあるカテゴリ名ごとにフォルダを作り、その中に記事を入れる方式でした。まずカテゴリがばらばらだったため、開発日誌別にカテゴリを新しく付与し、そのカテゴリごとにフォルダを作って記事を表示するようにしました。

### Astroの動的ルーティング活用
単に記事を並べるだけでなく、`/blog/categories/[category]`形式のURLでアクセスできるようにしたいと思いました。そのためAstroの**Dynamic Routing（動的ルーティング）**機能を活用しました。

`getStaticPaths`関数で全投稿（`getCollection('blog')`）を読み込んだあと、投稿のFrontmatterにある`category`情報を収集しました。
`Set`を使って重複カテゴリを除去し、各カテゴリ別にページパスを生成しました。これにより、カテゴリが増えても別作業なしでページが自動生成されるようになりました。

### ディテール: 固有のパステルトーン色を付与（Server-side Hashing）
最大の難関は**「フォルダの色」**でした。すべてのフォルダが同じ青色だと区別しづらく、かといってJavaScriptで毎回ランダムに色を付けると、ページロード時に色がちらつくFOUC問題があります。

これを解決するため、**サーバーサイドハッシュ(Server-side Hashing)**方式を導入しました。
カテゴリ名（文字列）をASCIIコードへ変換して合計し、事前定義した**パステルトーンパレット**の数で割って、固有のインデックスを取り出す方式です。

```typescript
// カテゴリ名に応じて固定色を付与するロジック
let hash = 0;
for (let i = 0; i < categoryValue.length; i++) {
    hash = categoryValue.charCodeAt(i) + ((hash << 5) - hash);
}
const colorIndex = Math.abs(hash) % PALETTE.length;

```

これにより、クライアントスクリプトなしでもビルド時に色が決定され、性能低下がなく、カテゴリ別に一貫した色を維持できます。

## シリーズ機能追加
複数回に続く記事を一つの流れとして見せるため、**Series機能**を追加しました。Frontmatterに`series`と`seriesOrder`を入れ、同じシリーズ名を持つ記事をまとめて並べ替えられるようにしました。

- **ソート規則**: `seriesOrder`昇順 → 同じ順序の場合は`pubDate`基準
- **進行表示**: 現在の記事がシリーズ全体の何番目かを表示（例: `8 / 10`）
- **ナビゲーション**: 本文下部に前編/次編リンクを提供

これにより、開発日誌のような連続記事を自然に探索でき、読者側でもより見やすくなりました。
