## 2. Evaluation Findings Status

### Implemented already

#### GA4 blocked by CSP

**Status**: Implemented

**Why**:
- `vercel.json` now includes `https://www.googletagmanager.com` in `script-src`.
- `vercel.json` also includes Google Analytics and Tag Manager connect domains in `connect-src`.
- `BaseHead.astro` includes the GA4 script and config block, and the current CSP now allows them.

**Conclusion**:
- This specific issue from `Eval.md` appears fixed.

#### ViewCounter slug inconsistency

**Status**: Implemented for current blog routes

**Why**:
- The dynamic blog route passes `postId={post.id}` into the layout at [src/pages/[lang]/blog/[...slug].astro](/Users/jeonghun/hun-bot-blog/src/pages/[lang]/blog/[...slug].astro#L82).
- The layout uses `const slug = postId ?? Astro.url.pathname;` at [src/layouts/BlogPost.astro](/Users/jeonghun/hun-bot-blog/src/layouts/BlogPost.astro#L43).
- In the current post rendering path, `postId` is supplied, so Redis keys are derived from a stable content ID rather than the pathname fallback.

**Caveat**:
- The fallback branch is still there, so the fix is behavioral rather than structural. If the layout is reused elsewhere without `postId`, the old inconsistency can return.

### Partially implemented

#### View counter API hardening

**Status**: Partially implemented

**What changed**:
- The API now suppresses duplicate increments for the same `IP + slug` pair for one hour using Redis `SET ... NX EX`.
- Evidence at [src/pages/api/views.ts](/Users/jeonghun/hun-bot-blog/src/pages/api/views.ts#L65).

**What is still missing**:
- No slug validation.
- No strong rate limiting.
- No bot filtering.
- IP extraction is simplistic and can be spoofable depending on proxy setup.

**Conclusion**:
- Better than the state described in `Eval.md`, but still not robust.

## 3. Net Assessment

### Already implemented

- GA4 CSP compatibility is fixed.
- View counter duplicate suppression exists.
- View counter slug handling is effectively stabilized for current post pages because `postId` is passed from the dynamic route.

### Not yet implemented

- All 8 items in `improve.md` are still pending.
- Most architectural and code-quality concerns in `Eval.md` are also still pending.

### Most important open items

1. Replace theme storage with `localStorage`.
2. Fix `getPostUrl()` to generate real language-aware blog URLs.
3. Remove duplicated KaTeX/math plugin registration.
4. Add slug validation and stronger abuse protection to the view counter API.
5. Implement at least one user-visible reading UX improvement from `improve.md`:
   progress bar, back-to-top button, listing read time, or pagination.

---

## 4. Recommended Next V1 Scope

If the goal is a realistic "V1 improvement pass", the best sequence is:

1. Fix correctness bugs first:
   theme persistence, `getPostUrl()`, breadcrumb i18n, math plugin duplication.
2. Fix trust and platform issues next:
   view counter validation/rate limiting, CSP tightening.
3. Then ship visible UX wins:
   read time on listing, progress bar, back-to-top button, pagination.
4. Then ship growth features:
   per-language RSS and Pagefind search.

This ordering gives the best ratio of user-visible improvement to engineering risk.
