# Learning Paths

Learning paths are hand-authored static guides that connect existing public posts with supporting Library resources, papers, and presentation metadata.

They are editorial surfaces, not recommendations generated by an algorithm.

## Routes

The current route convention is language-prefixed:

- `/ko/paths/`
- `/jp/paths/`
- `/en/paths/`
- `/ko/paths/{path-id}/`
- `/jp/paths/{path-id}/`
- `/en/paths/{path-id}/`

## Metadata

Learning path metadata lives in `src/data/learningPaths.ts`.

Each published path includes:

- `id`: slug-safe path ID.
- `status`: `published`, `draft`, or `archived`.
- localized `title` and `description`.
- `updatedAt`: `YYYY-MM-DD`.
- `minimumSteps`: minimum resolved public posts needed before display.
- `topicIds`, `resourceIds`, `paperIds`, and `deckIds`.
- ordered `steps` with localized editorial notes and post references.

## Post References

Steps can reference a post per language:

```ts
postIds: {
  ko: 'ko/devlog/blog/blog_develop_01',
  en: 'en/devlog/blog/blog_develop_01',
},
fallbackPostId: 'ko/devlog/blog/blog_develop_01',
```

If the current language is missing, the page uses `fallbackPostId` and labels the fallback language clearly.

## Publication Rules

- Publish only paths that point to reviewed public posts.
- Do not use paths to expose draft MDX, private candidates, raw notes, or unreviewed generated text.
- Keep path notes short and original.
- Do not invent supporting resources that are not in the public Library data.
- Keep optional deck references backendless and local.

## Validation

Run:

```sh
npm run paths:validate
npm run routes:validate
npm run content:validate
npm run build
```

The validator checks duplicate IDs, slug-safe IDs, post references, public Library references, deck references, route files, and generated output when build artifacts exist.
