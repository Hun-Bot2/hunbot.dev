# Security Risk Register

Reviewed: 2026-05-12

Do not print or commit secret values. A root `.env` file exists and was not read during this review.

Product direction reference: [`docs/decisions/discover-direction.md`](./discover-direction.md). Security work should preserve the public/private boundary: approved public content can live in Git, while private candidates, raw source text, embeddings, unreviewed AI output, and future commercial data stay outside the public repo.

| Risk ID | Severity | Affected files | Scenario | Recommended fix | Test or verification method | Status |
| --- | --- | --- | --- | --- | --- | --- |
| SEC-001 | High | `src/pages/api/views.ts`, `src/components/ViewCounter.astro` | The `slug` query parameter is accepted as a raw Redis key fragment. A client can create arbitrary high-cardinality keys or keys with unexpected separators. | Add a single slug validator that only accepts generated blog content IDs or a strict allowlist pattern. Build Redis keys through a helper that encodes or rejects invalid input. | `npm run views:validate`; smoke test `GET` and `POST` with valid, missing, malformed, and oversized slugs. | Implemented |
| SEC-002 | High | `src/pages/api/views.ts` | Duplicate suppression uses client IP plus slug for one hour, but there is no global per-IP rate limit, per-slug rate limit, or bot protection. | Add lightweight rate limiting with short TTL buckets before incrementing view counts. Keep localhost bypass behavior explicit. | `npm run views:validate`; monitor Redis key growth in staging. | Implemented |
| SEC-003 | Medium | `src/pages/api/views.ts` | IP extraction trusts a request header directly. Depending on proxy behavior, clients may influence the dedupe key. | Prefer the platform-provided client IP when available, parse only the first forwarded IP, and never log derived keys. | `npm run views:validate`; staging request check through Vercel logs without exposing IP-derived key values. | Implemented |
| SEC-004 | Medium | `src/pages/api/views.ts` | Redis credentials missing at runtime still constructs a client and the route fails only on use. | Fail closed with a clear non-secret error path when credentials are absent. Avoid printing values. | `npm run views:validate`; local run without credentials should return a controlled API error and no secret-bearing logs. | Implemented |
| SEC-005 | High | `vercel.json`, `src/components/BaseHead.astro`, component inline scripts | CSP allows inline scripts. This is currently compatible with the codebase but weakens XSS protection. | Continue extracting stable behavior into external scripts or Astro-safe modules, then remove `unsafe-inline` when every inline script has a replacement strategy. | `npm run csp:validate`; build and manual smoke test theme, menu, TOC, analytics, comments, and view counter after each CSP reduction. | In progress |
| SEC-006 | Medium | `src/components/BaseHead.astro`, `src/components/GiscusComments.astro`, `vercel.json` | Third-party scripts for analytics, comments, fonts, and math styles execute or load on public pages. | Keep an explicit third-party inventory, remove unused services, and avoid adding new script domains without CSP and privacy review. | `npm run csp:validate`; browser network audit on representative pages; CSP report-only trial before tightening. | Documented |
| SEC-007 | Low | `src/components/GiscusComments.astro`, `src/consts.ts` | Comments depend on public configuration and an external script. Misconfiguration can show comments for the wrong repository/category or fail open visually. | Validate required public comment config at build or render a disabled state. Keep fallback non-sensitive. | `npm run csp:validate`; manual page check with comments enabled and disabled; inspect rendered attributes for expected public identifiers only. | Implemented |
| SEC-008 | Medium | `src/content/blog/**/*.mdx`, future Library files | MDX content is executable at build time. If AI-generated or third-party content is imported without review, unsafe markup or code can be published. | Treat all generated translations, summaries, and Library content as drafts until human-reviewed. Avoid raw third-party MDX ingestion. | Content validation checklist; code review for any new MDX imports/components. | Needs manual review |
| SEC-009 | Medium | Future Library ingestion docs/data | Library ingestion may mix approved public data with private candidates or raw third-party data. | Store approved public entries separately from private candidate data. Require license, source, attribution, and human review metadata. | Add a validation script before publication once Library schema exists. | Planned |
| SEC-010 | Low | `.gitignore`, root `.env` | Secret files are ignored, but local agents can still read them accidentally. | Keep `.env` ignored, do not inspect it in routine reviews, and use placeholder examples only. | `git status --short` should not show secret files; review docs for absence of secret values. | Implemented |
| SEC-011 | Medium | `src/pages/[lang]/blog/categories/[category].astro` | Category route params are decoded and displayed. Static generation lowers risk, but future dynamic category routes could trust user-supplied path values. | Keep category pages generated from collection data only; encode links and normalize category identifiers if category routes become dynamic. | Build generated category pages; test categories with spaces, case differences, and reserved characters. | Planned |
| SEC-012 | Low | `src/components/BaseHead.astro`, `public/robots.txt` | Analytics and indexing behavior are enabled globally. Privacy and crawler behavior should be deliberate for future Library pages. | Add per-section opt-in or metadata controls before publishing sensitive Library/resource pages. | Manual review of robots, meta robots, and analytics loading on new Library routes. | Planned |
| SEC-013 | Medium | `src/pages/api/feedback.ts`, `src/utils/feedback.ts` | Anonymous feedback accepts unauthenticated writes. Without limits it is a spam and storage-cost target. | Keep the endpoint write-only with no `GET` handler, validate the slug with the shared pattern, cap message length, strip control characters, and rate limit far more tightly than the view counter (3 per 10 minutes vs 30 per minute). | `npm run product:validate` asserts the write-only property and approved route list; submit valid, oversized, malformed-slug, and repeated requests. | Implemented |
| SEC-014 | High | `src/pages/api/feedback.ts`, any future rendering surface | If stored feedback is ever rendered into a page, anonymous unsanitized text becomes public HTML. The repo has no HTML sanitizer dependency. | Never render stored feedback. Read it only through `scripts/read-feedback.mjs`. Publishing it requires a separate plan covering moderation, sanitization, and captcha. | `npm run product:validate` fails if a component renders feedback as markup or if a `GET` handler is added. | Implemented |
